# Agent 运行时路径角色设计

## 1. 设计目标

明确 Agent 运行时涉及的不同目录职责，避免所有路径都以 `cwd` 为根目录，导致 Agent 自身数据、用户工作区、访问权限和 Git 仓库相互混淆。

## 2. 路径角色

| 概念 | 建议名称 | 职责 | 典型内容 |
| --- | --- | --- | --- |
| Agent 自身目录 | `agentHome` | 保存 Agent 自己拥有的数据和资源 | `skills/`、`traces/`、`logs/`、`cache/`、`config/` |
| 默认工作目录 | `workspace` ` | 用户希望 Agent 默认工作的地方，也是相对路径的解析基准, 即启动时的cwd | 项目文件、默认创建的文件、Bash 初始目录 |
| 可操作目录集合 | `allowedRoots` | 定义 Agent 被允许访问和修改的目录范围 | 一个或多个 workspace、共享文档目录 |
| Git 仓库根目录 | `gitRoot` | Git 能力上下文，表示某次 Git 操作所属的仓库，由启动时cwd为基准动态发现 | `.git` 所在目录 |

这些概念表达的不是同一件事：

```text
agentHome       Agent 自己的数据放在哪里
workspace       默认在哪工作
allowedRoots    最多允许操作哪些位置
gitRoot  当前 Git 操作属于哪个仓库
```

## 3. 设计约束

1. `workspace` 是默认工作位置，不等于权限边界；`allowedRoots` 应按集合设计，以支持多个目录。
2. Agent 的内部运行记录与任务交付物应区分：前者属于 `agentHome`，后者可以放在 `workspace`。
