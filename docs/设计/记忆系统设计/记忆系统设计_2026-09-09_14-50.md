# 记忆系统设计

- 当前状态：当前设计

## 核心思路

记忆是工作区级、可读的长期状态：主题 Markdown 文件是事实来源，`MEMORY.md` 是派生索引。召回仍在主回答前按需进行；提取和整理改为主回答后的后台工作，不能增加用户等待时间。

后台任务采用至少一次执行：任务先持久化，文件写入成功后才删除任务。进程中断时允许重放并产生短期重复，整理器负责最终合并、更新和删除；不引入严格幂等、任务状态机或跨进程协调。

## 核心模块与职责

| 模块 | 核心方法 | 职责 |
| --- | --- | --- |
| `AgentSession` | `submitInternal()` | 主回答成功后读取当前 `turn_seq` 消息，并调用 `MemoryRuntime.enqueue(...)`；不等待后台处理。 |
| `SessionStore` | `listTurnMessages(...)` | 返回当前 Turn 的已提交协议消息，保留隐藏提醒、tool_use、tool_result。 |
| `MemoryRuntime` | `enqueue(...)`、`recall(...)` | 统一记忆开关、召回与后台工作入口；入队时冻结两份上下文。 |
| `MemoryWorkStore` | `enqueue(...)`、`pendingTasks()`、`completeTaskAndIncrement(...)` | 在 `.memory/memory-work.db` 持久化待提取任务和未整理新增数量。 |
| `MemoryBackgroundProcessor` | `wake()`、后台 drain、定时检查 | 单线程依次处理任务；每新增 5 个文件或每 2 小时存在未整理新增时调用整理。 |
| `MemoryExtractor` | `extract(task)` | 首轮只分析当前 Turn；信息不足时以同一任务冻结的 `modelContext` 发起第二次结构化请求；只返回候选。 |
| `MemoryRepository` | `createNew(...)` | 提取阶段只创建新主题文件；同名使用 `-2` 等新名称，绝不覆盖已有文件。 |
| `MemoryConsolidator` | `consolidate()` | 唯一允许归纳、更新、合并和删除既有记忆的组件。 |

## 关键边界

- `ConversationState` 不承载提取任务状态；后台只使用已冻结的上下文快照。
- 提取输入不再过滤隐藏提醒、工具调用或工具结果；它们均作为待分析数据，不是可执行指令。
- 后台入队或处理失败不影响已经完成的主回答；失败记录诊断，未完成任务保留重试。
- 记忆关闭时不入队、不召回、不处理既有任务；重新开启后继续消费遗留任务。
