# 2026-09-02 错误记录

## 21:43 Quillith 评测 Terminal-Bench 2.0 `regex-log`

### 1. 官方任务镜像不满足 Quillith 运行依赖

- 尝试了什么：直接对 `terminal-bench-sample@2.0` 的 `regex-log` 运行 `--install-only`。
- 为什么不行：官方 `ghcr.io/laude-institute/terminal-bench/regex-log:2.0` 镜像缺少 Java 21 或 git，Adapter 的 `command -v java && command -v git && test -x /bin/bash` 检查失败。失败 Job：`D:\learn_claudecode\harbor-lab\run-results-terminal-bench2-install-check\2026-09-02__21-14-40`。
- 伴随问题：Harbor 在 Windows 控制台打印失败汇总时，Rich 输出中的 `•` 无法由 GBK 编码，最终又抛出 `UnicodeEncodeError`，掩盖了前面的 Trial 原始错误。
- 最终采用什么方式：只修改本地下载任务的 Dockerfile，安装 `openjdk-21-jre-headless` 和 git；每次 launcher 调用前为 Harbor 子进程设置 `PYTHONUTF8=1`。没有在 Trial 运行期间安装依赖，也没有修改 Adapter。

### 2. 安装验证构建出的本地镜像未被普通正式运行复用

- 尝试了什么：安装验证使用 `--force-build` 成功后，按普通命令启动正式评测。
- 为什么不行：`task.toml` 仍声明官方 `docker_image`。正式运行不带 `--force-build` 时，Harbor 使用原始 registry 镜像，没有使用修改后的本地 Dockerfile，因此再次因缺少 Java 或 git 失败。失败 Job：`D:\learn_claudecode\harbor-lab\run-results\2026-09-02__21-20-29`。
- 最终采用什么方式：凡是依赖本地修改过的任务 Dockerfile，安装验证和正式评测都显式传入 `--force-build`。

### 3. `--install-only` 未覆盖 Agent 启动所需的 skills 目录

- 尝试了什么：在 Java、git、bash 和 JAR 安装验证全部通过后，使用本地镜像运行正式 Trial。
- 为什么不行：`--install-only` 只验证运行时命令和 JAR 可读性，不会真正创建 `AgentRuntime`。正式启动时 `SkillRegistry` 对 `/app/skills` 调用 `toRealPath()`，目录不存在导致 `NoSuchFileException`。失败 Job：`D:\learn_claudecode\harbor-lab\run-results\2026-09-02__21-21-31`。
- 最终采用什么方式：确认 Quillith 支持空技能注册表后，在 Trial Dockerfile 中创建空目录 `/app/skills`，重新执行安装验证和正式评测。未复制与任务无关的技能。

### 4. Agent 在模型连接抖动和过长正则调试中超时

- 尝试了什么：使用 `anthropic/qwen3.5-flash` 和任务默认 900 秒 Agent 超时运行修正后的 Trial 环境。
- 为什么不行：Agent 已创建 `/app/regex.txt`，过程中出现一次 `SSLHandshakeException: Remote host terminated the handshake`，Quillith 恢复后继续运行；但模型持续进行大量正则推理和 Perl 实验，最终达到 900 秒上限，Harbor 记录 `AgentTimeoutError`。
- verifier 结果：verifier 正常执行，reward 为 `0.0`。生成的正则在多日期行中返回首个日期，例如返回 `2023-12-31` 而不是最后一个 `2024-11-01`，同类错误也出现在 `2018-05-05` 与 `2018-06-06`。最终 Job：`D:\learn_claudecode\harbor-lab\run-results\2026-09-02__21-25-37`，失败 Trial：`regex-log__SSpevtM`。
- 结论：不能仅看 launcher 是否正常结束；必须同时检查 `n_errored_trials`、Trial `exception_info` 和 verifier 断言。本次不提高任务超时，也不把 verifier 失败改写为成功。
