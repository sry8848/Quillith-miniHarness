# 2026-09-03 错误记录

## 11:35 Codex Terminal-Bench 2 冷启动、认证与产物脱敏

### 1. 容器内在线安装 Codex 连续超时

尝试了什么：

- 使用 Harbor Codex Agent 的默认在线安装流程，在任务容器内执行 `apt-get update`，安装 curl、bash、Node.js、npm 和 ripgrep，再安装 Codex。
- 第一次使用默认 360 秒 Agent setup timeout。
- 第二次将 Agent setup timeout 提高到 1080 秒。

为什么不行：

- 两次都长时间停留在 Ubuntu 软件包下载阶段，分别在 360 秒和 1080 秒超时。
- Agent 尚未开始处理任务，继续单纯放大超时时间不能解决不稳定且昂贵的冷启动问题。

最终采用什么方式解决：

- 下载官方 npm 包 `@openai/codex@0.153.0-linux-x64`，提取 Linux 原生二进制。
- 运行 Trial 时把二进制目录只读挂载到容器 `/usr/local/bin`。
- Codex setup 降至约 1.6 秒，同时没有修改任务内容，最终 Trial 的任务 checksum 与 Quillith Trial 相同。

### 2. 临时软件源并不能稳定解决冷启动

尝试了什么：

- 在临时容器中测试阿里云 Ubuntu 镜像源。

为什么不行：

- HTTPS 源依赖 CA 证书，而原始基础镜像未预装 CA 证书。
- 改用 HTTP 后，约 13.1 MB 索引下载耗时约 8 分 32 秒，随后 universe 索引仍连接失败。

最终采用什么方式解决：

- 放弃在每个 Trial 内通过 apt/npm 在线安装完整工具链，改用只读挂载预先下载的官方原生二进制。

### 3. Harbor 优先选中了遗留的无效 API key

尝试了什么：

- 已挂载 Codex 二进制，直接使用 Harbor Codex Agent 运行任务。

为什么不行：

- 主机同时存在 Codex 的 ChatGPT 登录缓存和遗留的 `OPENAI_API_KEY`。
- Harbor 默认优先传入 API key；该 key 无效，Codex 重试后返回 HTTP 401，Trial 为 `NonZeroAgentExitCodeError`。

最终采用什么方式解决：

- 增加 Agent 环境变量 `CODEX_FORCE_AUTH_JSON=1`，明确让 Harbor 使用默认 Codex 登录缓存。
- `codex login status` 已确认当前为 ChatGPT 登录状态，随后同一任务 reward 为 1.0。
- 错误记录只保存认证来源和状态，不保存登录缓存或 API key 内容。

### 4. 隔夜恢复后 Docker daemon 未运行

尝试了什么：

- 在隔夜暂停后继续提交 Harbor Job。

为什么不行：

- Docker Desktop 已退出，Harbor 在创建 Job 前报告 Docker daemon 未运行。

最终采用什么方式解决：

- 启动 Docker Desktop，等待 daemon 可用后重新提交 Job。

### 5. Codex 下载产物被脱敏为无效 JSON

尝试了什么：

- 使用 PowerShell `ConvertFrom-Json` 读取成功 Trial 的 `result.json` 和 `agent/trajectory.json`，并按 JSONL 解析 `agent/codex.txt`。

为什么不行：

- 下载产物中的部分值被替换成未加引号的 `[REDACTED]`，使 `result.json` 和 `trajectory.json` 不再符合 JSON 语法。
- `codex.txt` 中也有少数事件行受相同问题影响，不能完全依赖逐行 JSON 解析统计。

最终采用什么方式解决：

- 本次记录使用 Harbor Job 汇总、verifier reward、verifier stdout 和原始事件文本交叉核对。
- 单独保存结构化的人工对比记录，不把损坏的 ATIF 文件当作唯一事实来源。
- 该方式只保证本次证据可追溯；若要批量自动统计，仍需修复或绕开产物脱敏链路。
