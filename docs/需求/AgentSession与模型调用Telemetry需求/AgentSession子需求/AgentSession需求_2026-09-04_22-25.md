# AgentSession 需求

## 一、目标

统一系统中 Agent 会话的业务概念，明确一段连续对话的历史、状态、生命周期和唯一身份。

本需求只建立 AgentSession，不包含 Turn、Trace、Span、模型调用 Telemetry 或其他观测能力的设计。

---

## 二、AgentSession 定义

`AgentSession` 表示一段连续的用户与 Agent 对话。

同一个 AgentSession 可以接收多次用户提交。多次提交共享同一份主对话历史，因此后续输入能够基于此前的用户消息、Agent 回复和工具交互继续执行。

系统统一使用 `AgentSession` 表达当前 `ManualAgent` 所承担的会话语义，不再把 ManualAgent 和 Session 定义为两个彼此独立的业务对象。

Agent 的模型调用、工具调用、Sub-Agent 调用和其他执行行为都发生在 AgentSession 内，不因此创建新的业务 Session。

---

## 三、SessionState

`SessionState` 表示一个 AgentSession 在生命周期内共享的状态。

系统统一使用 `SessionState` 表达当前 `AgentState` 所承担的会话状态语义，避免把会话状态误解为跨 Session 共享的 Agent 定义或 Agent 配置。

SessionState 包含当前会话需要持续共享的状态和上下文，包括：

```text
sessionId
memoryEnabled
approvalMode
agentHome
workspace
allowedRoots
gitRoot
```

其中可变状态继续按照当前业务规则更新，路径上下文和 `sessionId` 在 SessionState 创建后保持不变。

一个 AgentSession 只使用一份 SessionState。同一份 SessionState 不能同时属于多个 AgentSession。

---

## 四、Session Identity

每个 AgentSession 必须拥有唯一的：

```text
sessionId
```

`sessionId` 随该 AgentSession 的 SessionState 一起创建，并在 AgentSession 的整个生命周期内保持不变。

不同 AgentSession 必须使用不同的 `sessionId`。同一个 AgentSession 中的多次用户提交及其派生执行共享相同的 `sessionId`。

`sessionId` 是系统自身的业务 Identity，不能使用进程 ID、对象地址、模型响应 ID、工具调用 ID或观测系统生成的 ID 代替。

本阶段只建立 `sessionId`，不额外建立 `conversationId` 或其他含义相同的业务字段。

---

## 五、会话历史与状态归属

一个 AgentSession 只拥有一份主对话历史，一份主对话历史也只能属于一个 AgentSession。

AgentSession 持有主对话历史，并使用对应的 SessionState 完成会话范围内的状态读取和更新。

父 Agent 和由它发起的 Sub-Agent 属于同一个 AgentSession，共享同一份 SessionState 和 `sessionId`。

Sub-Agent 可以拥有完成自身任务所需的局部消息历史，但该局部历史不构成新的 AgentSession，也不替代 AgentSession 的主对话历史。

Session 内需要读取会话状态的组件必须使用同一份 SessionState，不得分别创建自己的 Session Identity 或会话状态副本。

---

## 六、生命周期

AgentSession 在一段新对话开始时创建，在该段对话明确结束时结束。

当前交互模式下，一次程序启动到退出对应一个 AgentSession。在此期间提交的多条普通用户输入属于同一个 AgentSession。

当前单次执行模式下，一次程序执行对应一个 AgentSession，其中包含一次用户提交。

当前 AgentSession 内的多次用户提交按顺序执行，本阶段不要求支持同一 AgentSession 内并发提交。

进程、Runtime 和底层资源当前可以与 AgentSession 同时创建和关闭，但它们的实例身份不能代替 `sessionId`。

---

## 七、本阶段边界

本阶段包括：

- 将当前 `ManualAgent` 的业务语义统一为 AgentSession；
- 将当前 `AgentState` 的业务语义统一为 SessionState；
- 建立每个 AgentSession 唯一且稳定的 `sessionId`；
- 明确主对话历史归 AgentSession 所有；
- 明确会话状态归 SessionState 所有；
- 保证父 Agent、Sub-Agent 和需要会话状态的组件使用同一份 SessionState；
- 保持同一个 AgentSession 中多次用户提交共享历史和状态。

本阶段不包括：

- Turn 的定义和 Identity；
- Trace 或 Span 生命周期；
- OpenTelemetry 属性记录；
- 模型调用 Telemetry；
- Logs、Transcript 和 Eval 接入；
- Session 持久化或查询；
- 进程重启后恢复旧 AgentSession；
- 一个 AgentSession 同时承载多份主对话历史；
- 同一个 AgentSession 内并发提交。
