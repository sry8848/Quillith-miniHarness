# AgentSession 需求

## 一、目标

统一系统中 Agent 会话的业务概念，明确一段连续对话的状态归属、生命周期和唯一身份，为后续关联 Trace、日志、Transcript、Eval 和其他运行时数据提供稳定的 Session 边界。

本需求只定义 AgentSession，不包含模型调用 Telemetry 的字段和记录规则。

---

## 二、AgentSession 定义

`AgentSession` 表示一段连续的用户与 Agent 对话。

同一个 AgentSession 中的多次用户提交共享同一份主对话历史，使后续输入能够基于此前的用户消息、Agent 回复和工具交互继续执行。

AgentSession 负责承载当前会话范围内持续存在的内容，包括：

```text
sessionId
主对话历史
会话状态
会话范围内的运行上下文
```

系统统一使用 `AgentSession` 表达当前 `ManualAgent` 所承担的会话语义，不再把 ManualAgent 和 Session 定义为两个彼此独立的业务对象。

Agent 的模型调用、工具调用和推理循环是 AgentSession 内发生的执行行为，不是新的 Session。

---

## 三、Session Identity

每个 AgentSession 必须拥有唯一的：

```text
sessionId
```

`sessionId` 在 AgentSession 创建时确定，并在该 AgentSession 的整个生命周期内保持不变。

不同 AgentSession 必须使用不同的 `sessionId`。同一个 AgentSession 中的所有用户提交及其派生执行必须共享相同的 `sessionId`。

`sessionId` 是系统自身的业务 Identity，不能使用以下 ID 代替：

```text
traceId
spanId
模型响应 ID
toolCallId
```

本阶段只建立 `sessionId`，不额外建立 `conversationId` 等含义相同的业务 ID。

---

## 四、会话历史与状态

一个 AgentSession 只拥有一份主对话历史。

同一份主对话历史不能同时属于多个 AgentSession，一个 AgentSession 也不能同时代表多段彼此独立的用户对话。

会话状态与主对话历史具有相同的 Session 生命周期。当前需要在多次用户提交之间保持的状态均属于对应 AgentSession。

由当前 AgentSession 发起的 Sub-Agent 执行仍属于同一个 Session，并继承相同的 `sessionId`。Sub-Agent 可以拥有完成自身任务所需的局部执行上下文，但不得因此创建新的业务 Session。

---

## 五、用户提交与 Turn

一次有效的：

```text
AgentSession.submit(...)
```

对应 AgentSession 中的一个 Turn。

一个 AgentSession 可以依次包含多个 Turn：

```text
AgentSession
├── Turn
├── Turn
└── Turn
```

Turn 是 AgentSession 上的一次执行，不是独立会话。

本阶段不为 Turn 创建额外的业务 `turnId`。Turn 的执行身份由对应的 OpenTelemetry Trace 表达。

输入未满足 `submit` 调用契约时不产生 Turn。输入通过调用契约校验后，即使随后被 Hook 阻止或执行失败，仍然视为一次已经发生的 Turn。

当前同一个 AgentSession 中的多次 `submit` 按顺序执行，本阶段不要求支持同一 AgentSession 内并发执行多个 Turn。

---

## 六、生命周期

AgentSession 在一段新对话开始时创建，在该段对话明确结束时关闭。

当前交互模式下，一次程序启动到退出对应一个 AgentSession。在此期间提交的多条用户输入属于同一个 AgentSession。

当前单次执行模式下，一次程序执行对应一个 AgentSession，其中包含一次用户提交。

进程、Runtime 和底层资源的生命周期不作为 AgentSession 的业务定义。当前实现可以让它们具有相同的创建和关闭时机，但不能使用进程 ID、对象地址或资源实例身份代替 `sessionId`。

---

## 七、Identity 传播

AgentSession 发起的执行链必须能够识别自己所属的 `sessionId`。

传播范围包括该 Session 内由用户提交直接或间接触发的：

```text
Agent 执行
模型调用
工具调用
Sub-Agent 执行
上下文处理
记忆处理
Trace
```

执行链中的下游模块只能继承当前 AgentSession 的 `sessionId`，不能分别生成新的 Session Identity。

异步执行如果属于当前 AgentSession 发起的任务，也必须保留该 AgentSession 的 `sessionId`。

---

## 八、与 OpenTelemetry 的关系

AgentSession 是业务概念，不依赖 OpenTelemetry 是否启用。

启用 OpenTelemetry 时，`sessionId` 应使用以下标准属性写入相关 Trace 和 Span：

```text
gen_ai.conversation.id
```

同一个 AgentSession 产生的多条 Trace 通过相同的 `gen_ai.conversation.id` 关联。

OpenTelemetry 未启用时，AgentSession 和 `sessionId` 仍然正常存在，不得从 Trace 或 Span 反向生成 Session Identity。

---

## 九、本阶段边界

本阶段包括：

- 建立统一的 AgentSession 业务语义；
- 建立每个 AgentSession 唯一且稳定的 `sessionId`；
- 明确主对话历史和会话状态的 Session 归属；
- 明确一次有效 `submit` 是 Session 内的一个 Turn；
- 将 `sessionId` 传播到 Session 内的派生执行；
- 允许后续 Trace、日志、Transcript 和 Eval 使用同一个 Session Identity。

本阶段不包括：

- 进程重启后恢复旧 AgentSession；
- Session 持久化和查询；
- 一个 AgentSession 同时承载多份主对话历史；
- 同一个 AgentSession 内并发执行多个 Turn；
- 独立 `turnId`；
- 模型调用 Telemetry 字段补充；
- Logs、Transcript、Eval 和其他模块的完整业务改造。
