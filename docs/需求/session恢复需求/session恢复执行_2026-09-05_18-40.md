# Session 恢复执行

## 一、执行结论

接受 `session恢复需求_2026-09-05_14-47.md` 的产品语义，不增加旧 `AgentLoop` 续跑、旧审批恢复、旧续写计数恢复或自动模型请求。

当前代码已经具备：

- `AgentSession` 持有主对话 `history`；
- `SessionState` 持有 `sessionId`；
- `AgentLoop` 负责把完整 assistant 块、工具调用和工具结果追加到 `history`；
- `InteractiveRunner` 在用户输入后才调用 `agentSession.submit(...)`。

当前缺口是：`history` 只在内存中，进程重启后无法恢复；工具执行中断时也没有持久化的 UNKNOWN 事实。因此本次只新增一个窄持久化边界，让 Session 恢复能够把未完成 Turn 封口为 `INTERRUPTED`，恢复本身不调用模型和工具。

## 二、文件级修改

### 1. 新增 `src/main/java/dev/learn/agent/manual/SessionStore.java`

新增类职责：

- 使用 `agentHome/.sessions/<sessionId>/state.json` 保存当前 Turn 状态；
- 使用 `agentHome/.sessions/<sessionId>/history.jsonl` 保存可恢复的 `MessageParam` 历史；
- 新建 Session 时创建空历史和 `IDLE` 状态；
- 恢复 Session 时读取历史；
- 如果恢复时发现状态是 `RUNNING`，追加中断说明并把状态写回 `IDLE`；
- 如果最后一条历史是未配对的 assistant `tool_use`，追加同 ID 的 `tool_result`，内容明确说明 `UNKNOWN`，并要求下一 Turn 先检查现实状态。

核心伪代码：

```java
public final class SessionStore {
    enum TurnStatus {
        IDLE,
        RUNNING
    }

    public static SessionStore open(Path agentHome, String sessionId) throws IOException;

    public static ResumeResult resume(Path agentHome, String sessionId) throws IOException {
        SessionStore store = open(agentHome, sessionId);
        SessionSnapshot snapshot = store.load();
        List<MessageParam> history = new ArrayList<>(snapshot.history());

        if (snapshot.turnStatus() == TurnStatus.RUNNING) {
            boolean hasUnknownTool = appendInterruptedMarker(history);
            store.saveIdle(history);
            return new ResumeResult(store, List.copyOf(history), true, hasUnknownTool);
        }

        return new ResumeResult(store, List.copyOf(history), false, false);
    }

    public void saveRunning(List<MessageParam> history);

    public void saveIdle(List<MessageParam> history);
}
```

实现细节：

- `MessageParam` 序列化和反序列化复用 `ObjectMappers.jsonMapper()`；
- `history.jsonl` 每行一条 `MessageParam`，不自定义消息协议；
- 写入时先写临时文件，再使用 `ATOMIC_MOVE` 替换目标文件；
- `--resume` 传入的 `sessionId` 使用 `UUID.fromString(...)` 校验，避免路径穿越；
- 持久化失败直接抛出，不降级成“恢复成功”。

### 4. 修改 `src/main/java/dev/learn/agent/manual/ManualAgentApplication.java`

创建 `SessionState` 前判断 `options.resumeSessionId()`：

```java
SessionStore sessionStore;
List<MessageParam> initialHistory;
boolean previousTurnInterrupted;
boolean hasUnknownTool;

if (options.resumeSessionId() == null) {
    sessionState = new SessionState(...);
    sessionStore = SessionStore.open(agentHome, sessionState.sessionId());
    sessionStore.saveIdle(List.of());
    initialHistory = List.of();
} else {
    sessionState = new SessionState(options.resumeSessionId(), ...);
    ResumeResult resumeResult = SessionStore.resume(agentHome, options.resumeSessionId());
    sessionStore = resumeResult.sessionStore();
    initialHistory = resumeResult.history();
    previousTurnInterrupted = resumeResult.previousTurnInterrupted();
    hasUnknownTool = resumeResult.hasUnknownTool();
}
```

交互模式启动后只打印恢复状态：

```text
Session <id> restored.
Previous turn was interrupted.
One or more tool executions have unknown outcomes.
```

不调用 `agentSession.submit(...)`，不触发模型和工具。

### 6. 修改 `src/main/java/dev/learn/agent/manual/AgentSession.java`

构造函数新增 `SessionStore` 和 `initialHistory` 重载。

`submit(...)` 修改：

1. 添加用户消息后立即 `sessionStore.saveRunning(history)`；
2. Hook 追加上下文后再次保存 RUNNING；
3. `agentLoop.run(...)` 正常返回后，记忆完成前后不改变 Turn 状态；
4. 记忆完成后 `sessionStore.saveIdle(history)`；
5. Provider 最终失败时先保留现有诊断和回滚，再 `sessionStore.saveIdle(history)`，最后继续抛给 Runner。

Provider 最终失败仍沿用现有失败语义，不伪装成中断恢复。

### 7. 修改 `src/main/java/dev/learn/agent/manual/AgentLoop.java`

构造函数新增 `SessionStore sessionStore`。

每次真实 `messages` 被修改后调用：

```java
sessionStore.saveRunning(messages);
```

包括：

- BeforeModelCall Hook 追加隐藏上下文；
- ContextManager 完成 snip / compact 后替换真实历史；
- 普通 assistant 消息提交；
- 输出续写提示提交；
- Stop Hook 继续提示提交；
- assistant tool_use 和 user tool_result 成对提交；
- SSE Provider Error 恢复事实提交；
- 流中断恢复事实提交。

工具 UNKNOWN 的关键改动在 `executeTool`：

```java
if (approvalGate.approve(effectiveToolCall)) {
    markToolStarted.run();
    executionResult = toolRegistry.execute(effectiveToolCall);
}
```

`markToolStarted` 在工具通过审批后、进入 `ToolRegistry.execute(...)` 前，保存一份“当前历史 + 已完整关闭 assistant 内容块”的 RUNNING 快照。

这样：

- 审批提示阶段中断：不会记录 tool_use，恢复后不产生 UNKNOWN；
- 工具已经开始执行后中断：恢复时能看到未配对 tool_use，并追加 UNKNOWN tool_result；
- 工具结果已经成对提交后中断：恢复时保留 SUCCEEDED 或 FAILED 结果，不重复执行。

- 不恢复 JVM 调用栈；
- 不恢复旧 `AgentLoop` 控制流；
- 不从旧 Turn 的某个 phase 自动继续；
- 不自动调用模型；
- 不自动执行工具；
- 不恢复旧审批请求；
- 不恢复输出续写次数；
- 不恢复模型轮次；
- 不恢复 compact/summary 的中间状态；
- 不新增 Turn ID；
- 不新增 Session 查询列表、删除、重命名或迁移能力；
- 不把 Harbor 同进程 resume 改造成跨进程恢复。
