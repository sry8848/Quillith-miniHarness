# Quillith 对话记忆评测需求技术评审

## 1. 评审对象

对应需求：[Quillith 对话记忆评测需求](./Quillith对话记忆评测需求_2026-09-06_20-26.md)。

本评审只确定固定对话如何经过 Quillith 真实运行时路径，不选择具体题目，不设计 verifier，不设计 Memory 或压缩改进方案。

## 2. 现有代码约束

### 2.1 主模型输出由 AgentLoop 产生

`AgentSession.submit()` 只接收用户输入。正常路径内，`AgentLoop` 在每个业务模型 Round 开始前执行 Hook 和上下文治理，然后调用 `runIteration()` 取得主模型响应。

因此，如果在 `AgentSession` 外部直接替换最终 history，就会绕过历史增长过程中的上下文治理。

### 2.2 模型客户端是共享依赖

`AgentRuntime` 当前创建一个 `AnthropicClient`，并将它同时交给主 Agent、上下文压缩和 Memory。

因此，在 Quillith 之外简单替换 Provider 地址，会同时接管主模型、压缩模型和 Memory 模型请求，不能直接满足“只固定历史 assistant，其他模型调用保持真实”的要求。

### 2.3 当前没有历史回放边界

`streamModel()` 同时处理 Provider SSE、内容块确认、工具调度和流式持久化。它是面向在线执行的方法，不是可直接填充已完成 assistant 消息的回放接口。

本需求因此需要在 Quillith 中增加一个最小回放边界。

## 3. 方案比较

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 复制 `AgentLoop` 后改造 | 不修改现有 Agent 源码 | 回放程序与生产路径分叉；压缩或 Memory 变更后需要人工同步 | 不采用 |
| 外部伪 Provider 或请求代理 | Quillith 核心代码可以不改 | 需要识别并转发压缩和 Memory 请求，同时模拟主模型 SSE；总体复杂度更高 | 不采用 |
| 在现有 Turn 路径增加通用回放分支 | 共用真实 Session、压缩和 Memory 实现；没有核心逻辑副本 | 需要在主路径中保留一次 recorded/live 选择 | 采用 |

## 4. 技术结论

Quillith 增加一个通用的固定 assistant 响应回放能力。当前 Turn 未提供固定响应时，完全执行现有真实模型路径；提供固定响应时，在完成请求前 Hook 和上下文治理后，跳过本次主模型生成，将固定 assistant 作为已完成响应交给现有的 Turn 提交路径。

recorded/live 两种行为之间必然存在一次选择。本评审接受一个局部、直接的条件分支，不为隐藏该分支而拆分整个 `streamModel()`、新增策略类层级或引入通用模型提供者框架。

该分支只能判断当前 Turn 是否已提供固定响应，不能判断 Harbor 任务名、评测集名称或题型。

## 5. 概念路径

### 5.1 历史回放

```text
Harbor 评测编排
→ 提供一组原始 user/assistant
→ user 进入 AgentSession 的正常 Turn 边界
→ 执行现有 Hook、Memory 准备和上下文治理
→ 使用固定 assistant 取代本次主模型生成
→ 执行现有消息提交、Session 持久化和 Memory 完成逻辑
→ 处理下一组 user/assistant
```

回放是一个按顺序发生的运行过程，不是 Session 导入。

### 5.2 最终提问

```text
历史回放完成
→ 不提供固定 assistant
→ 执行现有真实主模型路径
→ 产生待评分答案
```

上下文压缩模型和 Memory 内部模型调用始终保持真实，不受历史 assistant 回放的影响。

## 6. 模块责任

### 6.1 Harbor 评测目录

负责：

- 保存和加载官方评测数据；
- 选择题目与保留原始分类；
- 将数据转换为通用的 user/assistant 回放请求；
- 编排单对话和跨对话运行；
- 执行评分并保存结果。

### 6.2 Harbor 机器输入边界

负责传输已经准备好的回放 Turn 和真实提问 Turn。它可以扩展现有机器协议，但不解析特定评测集格式。

### 6.3 AgentSession

负责让真实提交和固定响应提交共用同一套 Turn 外层行为，包括用户消息、Session 状态与 Memory 生命周期。

### 6.4 AgentLoop

负责保留现有 Hook 和上下文治理顺序，并在完成这些公共步骤后，对本次响应执行 recorded/live 选择。

### 6.5 现有上下文和 Memory 模块

`ContextManager`、`MemoryRuntime` 和 `SessionStore` 不感知响应来自真实模型还是历史回放，不加入评测分支。

## 7. 预计代码变化范围

后续执行方案只应覆盖以下职责：

1. 表示一次已完成的固定 assistant 文本响应；
2. 从 Harbor 机器输入边界提交一组 user/assistant；
3. 让 `AgentSession` 复用现有 Turn 生命周期；
4. 在 `AgentLoop` 中增加一处局部的 recorded/live 分支；
5. 固定响应耗尽或未提供时，使用现有真实模型路径。

本评审不要求搬移或重写现有 `streamModel()`、工具执行、错误恢复、压缩或 Memory 逻辑。具体类名、方法签名和机器协议格式留待执行前的代码方案确认。

## 8. 性价比结论

局部回放分支会让 Quillith 核心路径多一个明确状态，但它换来了以下收益：

- 评测持续使用真实压缩与 Memory 实现；
- 当这些实现变化时，不需要同步一份 Agent 副本；
- 历史 assistant 固定后，可以把评测变化更集中地归因于上下文和 Memory；
- 测评数据和产品逻辑保持隔离。

相比之下，复制 Agent 逻辑或建立模型代理都会为了避免一个局部分支而引入更多代码和更难证明的一致性，不符合当前 mini harness 的范围。

## 9. 本评审未决定的事项

以下事项不在本文档中预先决定：

- 具体选用哪些官方评测集和题目；
- 固定响应的机器传输格式；
- 具体类名和方法签名；
- verifier 和结果文件格式；
- 结构化 `tool_use/tool_result` 轨迹回放；
- 基线之后的压缩、Memory 和 RAG 改进方案。

这些内容应结合后续选定的真实数据和实际基线结果继续补充。

## 10. 调研依据

- LongMemEval 将历史表示为按顺序排列的 `user/assistant` 消息，并允许将带时间的历史直接提供给待测系统：<https://github.com/xiaowu0162/LongMemEval>
- LangChain 的 Agent 测试使用按顺序返回固定响应的 fake model，使 Agent executor 继续运行原本流程：<https://github.com/langchain-ai/langchain/blob/master/libs/langchain/tests/unit_tests/agents/test_agent.py>
- Semantic Kernel 将函数调用和函数结果作为可显式构造的对话历史内容：<https://github.com/MicrosoftDocs/semantic-kernel-docs/blob/main/semantic-kernel/concepts/ai-services/chat-completion/chat-history.md>
- OpenClaw 的 mid-turn 检查位于工具结果进入历史之后、下一次模型请求之前，说明压缩边界应随模型 Round 而不是随流式增量划分：<https://github.com/openclaw/openclaw/blob/main/docs/reference/session-management-compaction.md>
