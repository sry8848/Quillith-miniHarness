# Quillith 对话记忆评测需求

## 1. 需求背景

Quillith 定位为可以实际使用的 Agent 核心机制 mini harness。当前已经具有 Session、上下文压缩和持久化 Memory，但还没有用外部评测集量化这些机制共同工作时的实际效果。

本需求先建立可重复的对话记忆评测能力，获得当前实现的基线结果，再根据真实失败决定如何改进上下文压缩和 Memory。

## 2. 评测目标

评测只关注两种用户可感知的记忆能力：

1. 单对话记忆：历史信息和最终问题位于同一个 Quillith Session；
2. 跨对话记忆：历史信息位于旧 Session，最终问题在不继承旧上下文的新 Session 中提出。

两类评测都使用 Quillith 当前的上下文压缩与 Memory，评价它们共存时的整体回答能力。本需求不把压缩单独拆成第三类评测目标。

## 3. 固定对话的回放要求

评测历史中的 `user` 和 `assistant` 消息必须按原始顺序进入 Quillith。

- `user` 消息作为真实用户输入进入当前 Turn；
- 历史 `assistant` 消息使用评测集给定的固定内容，不让当前模型重新生成；
- 最终问题由真实主模型回答；
- 回放必须逐轮进行，不能一次性用完整记录替换最终 history。

逐轮回放期间必须继续经过 Quillith 现有的 Session、上下文治理、Checkpoint 和 Memory 生命周期，不得在评测实现中复制一套替代逻辑。

上下文压缩点由 Quillith 自身策略决定，不在评测消息中插入人工“压缩点”。在模型上下文能力较小或需要确保触发压缩时，可以调低 Quillith 的压缩触发阈值，但不改写原始对话内容。

## 4. 评测数据要求

第一阶段从公开官方评测集中，按不同记忆能力类型选择若干典型题目，先少后多、先简单后困难。

官方原题必须先按原始内容运行并保留结果。如果失败由模型能力或上下文限制导致，后续可以增加改造题或自创题，但必须与官方原题分类记录，不得混合成同一组官方成绩。

## 5. 代码与测评责任边界

Quillith 只提供通用的固定 assistant 响应回放能力。

评测集的下载、加载、题型筛选、Session 编排、答案和评分全部位于独立的 Harbor 评测目录。Quillith 源码中不得出现特定评测集名称、题型判断、标准答案或数据路径。

## 6. 本阶段边界

本阶段不实现：

- 基于 RAG 的长期记忆改进；
- 针对压缩器的独立评分体系；
- 将完整 Agent 源码复制到评测目录后修改；
- 实际评测题目、verifier 和验收用例的具体选择；
- 当前选定的普通文本对话之外的工具轨迹回放。

RAG 作为后续长期记忆改进候选，在基线评测和问题定位完成后再单独评审。
