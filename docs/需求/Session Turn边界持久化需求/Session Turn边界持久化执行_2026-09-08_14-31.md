# Session Turn 边界持久化执行

## 最小修改

只改 `SessionState`、`AgentSession`、`SessionTurnJournal`、`SessionStore` 及其测试。`AgentLoop` 不接收新参数：它已经只经由 `TurnJournal` 写 canonical message，Journal 从 `SessionState` 读取当前 Turn 序号。

不实现 Turn 表、压缩按 Turn 的查询接口、in-flight 新列或 Provider 失败删除逻辑。

## 当前代码分析

- `AgentSession.submitInternal()` 在写入首条用户消息前进入本次业务 Turn；这里是唯一确定新 Turn 序号的位置。
- `AgentSession` 直接写入用户消息和 `UserPromptSubmit` Hook reminder；`AgentLoop` 的其他正式消息都通过 `SessionTurnJournal` 写入。
- `SessionStore.insertMessages()` 是所有 `messages` 写入的公共 SQL 汇合点。把 `turnSeq` 传到这里即可覆盖普通追加、完成封口和恢复封口。
- `AgentSession.resume()` 已先加载完整 messages，再在存在 in-flight 时调用 `commitCompletedTurn()` 封口。因此仅需在封口前恢复最后一条消息的 Turn 序号。

## 修改步骤

1. 修改 `src/main/java/dev/learn/agent/manual/SessionState.java`。

新增可变字段 `turnSeq`，以及包内方法：

```java
void beginTurn(long turnSeq) {
    this.turnSeq = turnSeq;
}

long turnSeq() {
    return turnSeq;
}

void restoreTurnSeq(long turnSeq) {
    this.turnSeq = turnSeq;
}
```

保留现有 `sessionId` 的创建、恢复和新建逻辑，不把 Turn 序号变成 Session 身份的一部分。

2. 修改 `src/main/java/dev/learn/agent/manual/AgentSession.java`。

在 `submitInternal()` 的开头、Telemetry 和 Hook 之前确定 Turn 序号：未持久化的首个 Session 使用 `0`；已有 Session 调用 `sessionStore.nextTurnSequence(sessionId)`，其 SQL 为 `MAX(turn_seq) + 1`。然后调用 `sessionState.beginTurn(turnSeq)`。

随后把直接调用 Store 的三处改为传入 `sessionState.turnSeq()`：首条用户消息、`UserPromptSubmit` Hook reminder 和 `resume()` 的恢复封口。

```java
sessionStore.createSessionWithFirstMessage(sessionId, workspace, turnSeq, userMessage);
sessionStore.appendCommitted(sessionId, turnSeq, List.of(message));
```

扩展 `SessionStore.LoadedSession`，带回该 Session 最后一条 message 的 `latestTurnSeq`。`resume()` 仅在 `loaded.inflight() != null` 时、调用 `commitCompletedTurn()` 前执行：

```java
sessionState.restoreTurnSeq(loaded.latestTurnSeq());
```

这保证修复消息继承被中断 submit 的序号；没有 in-flight 时不恢复 Turn 序号，因为下一次 `submitInternal()` 会读取新值。

3. 修改 `src/main/java/dev/learn/agent/manual/session/SessionTurnJournal.java`。

把 `appendCommitted()` 和 `commitCompletedTurn()` 转发为带 `sessionState.turnSeq()` 的 Store 调用。流式事实表不增加 Turn 序号，也不改 `TurnJournal` 接口。

4. 修改 `src/main/java/dev/learn/agent/manual/session/SessionStore.java`。

- 新库建表 SQL 将 `messages` 定义为 `turn_seq INTEGER NOT NULL`，主键仍为 `(session_id, seq)`。
- 初始化时检查 `PRAGMA table_info(messages)` 是否有 `turn_seq`。缺列时执行：

```sql
ALTER TABLE messages ADD COLUMN turn_seq INTEGER NOT NULL DEFAULT 0;
```

SQLite 会用默认值 `0` 填充旧行。所有旧消息归入该 Session 的 Turn `0`，其后新增 Turn 从 `1` 开始。无法可靠地从历史 `MessageParam` 反推旧 submit 边界；将整段旧历史作为一个 Turn 能保证不拆开既有工具协议，且不伪造边界。

- 新增 `nextTurnSequence(sessionId)`，查询该 Session 的 `COALESCE(MAX(turn_seq) + 1, 0)`。为 `createSessionWithFirstMessage`、`appendCommitted`、`commitCompletedTurn` 以及私有 `insertMessages` 增加 `long turnSeq` 参数。`insertMessages` 的 SQL 改为写入 `session_id, seq, turn_seq, message_json`。
- `loadSession()` 在读取 messages 时一并取得最后一行的 `turn_seq`，并写入 `LoadedSession.latestTurnSeq`。保留其对外提供的 `List<MessageParam>`，不引入消息实体或 Repository 层。

5. 修改测试。

- 在 `AgentSessionTest` 新增两次普通 `submit()` 的持久化断言：每个 Turn 内 user/assistant 的 `turn_seq` 一致，两次为 `0`、`1`。
- 在已有 in-flight 恢复测试中断言修复后新增的 assistant/tool-result/recovery message 与中断前最后一条 committed message 的 `turn_seq` 相同。
- 在 `SessionStoreTest` 建一个只有旧三列的 SQLite `messages` 表并插入同 Session 的多条旧消息；构造 `SessionStore` 后断言迁移完成、旧记录均为 `0`，并能追加 Turn `1` 的消息。
- 保留并运行现有“首次 Provider 失败后用户输入仍是持久化事实”测试，不改预期。

