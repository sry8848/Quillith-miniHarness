# 后台记忆提取与整理需求

## 设计目的

记忆提取和整理不得延长用户等待主回答的时间。主回答完成后只持久化一项待处理任务，随后立刻返回；后台以低频整理控制重复、冲突和过期记忆。任务必须不丢，但允许重复执行；短期重复由整理器最终收敛。

## 已确认需求

1. 回合结束时持久化待提取任务，其中保存本轮上下文和冻结的 `modelContext` 快照；应用重启后继续处理未完成任务。
2. 提取器先只分析本轮上下文；需要更多信息时，再以同一任务冻结的完整 `modelContext` 发起第二次结构化提取。它不读取原始 Session 历史。
3. 两份上下文均不得过滤工具调用、工具输出或隐藏提示；它们按模型上下文中的最终形态保存。
4. 提取只创建新记忆文件，不修改、合并或删除已有文件。同名候选使用简单新名称，不能覆盖旧文件。
5. 整理是唯一可归纳新增与既有记忆、更新、合并和删除记忆的阶段。
6. 每成功创建 5 个新记忆文件时整理一次；每 2 小时检查一次，只要尚有未整理的新增记忆就整理。计数仅在整理成功后重置，并持久化在 `.memory`。
7. 不增加独立常驻服务。应用运行时立即处理队列，并在每次两小时检查时扫描遗留任务；退出时未完成任务保留给下次启动。

## 控制边界

- 同一工作区的任务、提取、写入和整理必须串行；数量触发与定时触发重合时只整理一次。
- 任务只在全部创建完成后删除并累计新增数。进程在此之前中断时允许重放整个任务并产生短期重复；不为此增加严格幂等或恢复协议。
- 后台化不保证本轮新增记忆会立刻被下一轮召回；任务保存失败或后台失败不影响已完成的主回答，但必须留下诊断并保留可重试状态。
- 本轮不做跨进程协调、不回读原始 Session 详情、不增加通用 Agent 工具、重试框架、任务管理命令或新的配置项，也不改变现有整理内容规则。
