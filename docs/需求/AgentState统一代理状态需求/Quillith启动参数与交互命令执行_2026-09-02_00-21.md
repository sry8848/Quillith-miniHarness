现有主调用链已经满足动态状态传播：

```text

  -> ManualAgentApplication 创建唯一 AgentState
  -> AgentRuntime 把同一 AgentState 注入父子 Agent、MemoryRuntime、ToolApprovalGate

```

因此本轮不得新增事件总线、状态监听器、Command 接口、Command Registry、配置对象层或新的 Session 抽象。

## 3. 需要明确暴露的交互决策

源设计没有规定以下细节。为了使后面的代码说明可直接落地，本文给出最小推荐值，但执行代码前应由用户确认；如果选择不同，只调整对应测试和 Runner 分支，不扩大架构。

### 3.1 Exec 显式 ASK 的输入来源

推荐行为：

```text
Quillith exec --permission=ask <instruction>
```

从当前进程的 `System.in` 读取工具审批；默认 BYPASS 时仍不创建 `Scanner`。没有输入或输入流结束时保留当前 Gate 的直接失败语义，不自动降级为 BYPASS，也不吞错。

原因分别如下：

- WHAT：公共启动配置同时适用于 Interactive 和 Exec，因此 Exec 不能解析出 ASK 后仍以 BYPASS 执行。
- WHY：既然用户显式选择 ASK，静默改成 BYPASS 会违反权限语义；直接拒绝 ASK 又会让公共参数在 Exec 中名存实亡。

### 3.2 空行

推荐行为：空行只开始下一次读取，不退出，也不提交模型。

- WHAT：删除当前“空行退出”逻辑，增加 `command.isEmpty()` 的 `continue`。
- WHY：设计只声明 `/exit` 退出；但空字符串也不属于“其他文本”，没有必要为它发起一次空 Prompt 模型调用。

### 3.3 未知 Slash Command 和非法参数

推荐行为：所有 `/` 开头输入都在 CLI 层消费。未知命令打印：

```text
未知命令：<command-name>
```

已知命令参数错误打印各自用法，不进入 Agent Prompt。

- WHAT：`/unknown`、`/memory status`、`/exit now` 都不调用 `ManualAgent.submit()`。
- WHY：输入分类已经规定 `/` 前缀属于 CLI；把无法识别的 Slash 输入发送给模型会破坏这个边界。

### 3.4 大小写、无参数查询和重复启动参数

推荐保持当前最小兼容语义：

- CLI 参数值保持小写精确匹配，例如只接受 `--permission=ask`，与现有 `--memory=on` 一致。
- Runtime Command 保持当前大小写不敏感。
- 继续使用 `query.trim()` 后的文本判断命令，因此前面只有空白的 `/memory` 仍属于 Runtime Command；这延续当前 CLI 的输入归一化方式。
- `/memory` 等价于 `/memory state`；`/permission` 等价于 `/permission state`。设计中的方括号表示参数可省略。
- 同一种启动参数重复出现时最后一个生效，延续当前 `--memory` 的循环覆盖行为。
- Exec 仍只解析 instruction 之前的 `--` 参数；instruction 开始后的文本全部属于 instruction。

### 3.5 `Quillith` 可执行入口不在本轮自行发明

当前模块只有 Maven 工程和 `ManualAgentApplication.main()`，没有名为 `Quillith` 的脚本、可执行包或发布配置。设计中的调用名尚未映射到具体交付制品。

本轮只保证 `main(String[] args)` 接收的参数语义正确，不新增 Maven Shade、Assembly、启动脚本或改 artifactId。产品制品形式应在 Harbor 兼容层执行设计前单独确认。

新增：

```java
/**
 * 执行一条 Interactive Runtime Command。
 *
 * @param command 已去除首尾空白的 Slash Command
 * @param manualAgent 当前 Session 的父 Agent
 * @return true 表示结束 Interactive 循环，false 表示继续读取
 */
private static boolean handleRuntimeCommand(
        String command,
        ManualAgent manualAgent
) {
    String[] parts =
            command.split(
                    "\\s+",
                    2
            );
    String commandName =
            parts[0];
    String argument =
            parts.length == 1
                    ? ""
                    : parts[1].trim();

    if ("/memory".equalsIgnoreCase(commandName)) {
        handleMemoryCommand(
                argument,
                manualAgent
        );
        return false;
    }

    if ("/permission".equalsIgnoreCase(commandName)) {
        handlePermissionCommand(
                argument,
                manualAgent
        );
        return false;
    }

    if ("/exit".equalsIgnoreCase(commandName)) {
        if (argument.isEmpty()) {
            return true;
        }

        System.out.println(
                "用法：/exit"
        );
        return false;
    }

    System.out.println(
            "未知命令："
                    + commandName
    );
    return false;
}
```

返回 boolean 已足够表达当前唯一控制流，不新增 CommandResult 或枚举。

```java
/**
 * 查询或修改当前 Session 的工具审批模式。
 *
 * @param argument state、ask、bypass 或空字符串
 * @param manualAgent 当前 Session 的父 Agent
 */
private static void handlePermissionCommand(
        String argument,
        ManualAgent manualAgent
) {
    if ("ask".equalsIgnoreCase(argument)) {
        manualAgent.setApprovalMode(
                ToolApprovalMode.ASK
        );
        System.out.println(
                "[Permission：ASK]"
        );
        return;
    }

    if ("bypass".equalsIgnoreCase(argument)) {
        manualAgent.setApprovalMode(
                ToolApprovalMode.BYPASS
        );
        System.out.println(
                "[Permission：BYPASS]"
        );
        return;
    }

    if ("state".equalsIgnoreCase(argument)
            || argument.isEmpty()) {
        System.out.println(
                "[Permission："
                        + manualAgent.approvalMode()
                        + "]"
        );
        return;
    }

    System.out.println(
            "用法：/permission state | /permission ask | /permission bypass"
    );
}
```

输出直接使用 `ASK`、`BYPASS` 这两个产品词，不再引入“已开启/已关闭”映射，因为 Permission 不是布尔开关。
