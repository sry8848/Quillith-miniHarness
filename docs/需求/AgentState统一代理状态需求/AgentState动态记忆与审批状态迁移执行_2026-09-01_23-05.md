# AgentState 动态记忆与审批状态迁移执行

## 1. 文档定位

本执行文档在 `AgentState` 核心对象和唯一 Session 装配已经完成后，迁移两个运行期可变状态：

```text
memoryEnabled
approvalMode
```

目标不是增加新命令，而是确保所有现有消费者在每次使用时读取同一份 `AgentState`，修改后无需重建父 Agent、SubAgent、MemoryRuntime 或 ToolApprovalGate。

## 2. 前置依赖

必须先完成：

```text
AgentState核心模型与Session装配执行_2026-09-01_23-05.md
```

本轮假设：

- Interactive 创建的状态初始为 `ASK`，并向 Gate 提供共享 `Scanner`。
- Exec 创建的状态初始为 `BYPASS`，Scanner 继续为 `null`。
- 本轮没有允许 Exec 在运行中切换为 `ASK` 的入口。

## 3. 本轮明确不做

- 不实现 `/permission` 或新的 CLI 参数。
- 不修改 `ToolApprovalPolicy` 的分类规则。
- 不增加状态变更事件、观察者或回调。
- 不让 SubAgent 使用 `MemoryRuntime`。
- 不把 Memory 仓库迁移到 `agentHome`。
- 不改变 Memory recall、capture、complete 的调用顺序。
- 不改变 ASK 的终端文案或父子 Agent 共用 Scanner 的行为。

## 4. 先写测试

### 4.1 `ToolApprovalGateTest`

先把测试夹具改为使用 `AgentState`，再新增动态切换用例：

1. 同一个 Gate 在 `ASK` 下对 `REQUIRED` 调用读取 Scanner 并可拒绝。
2. 调用 `agentState.setApprovalMode(BYPASS)` 后，同一个 Gate 的下一次 `REQUIRED` 调用直接放行，不再读取新的终端输入。
3. 从 `BYPASS` 切回 `ASK` 后，同一个 Gate 的下一次调用重新询问。
4. `NOT_REQUIRED` 在两种模式下都直接放行。
5. 父、子两个 AgentLoop 共用的同一个 Gate 在状态切换后都遵循新模式；用行为验证，不增加 Gate mode getter。

测试必须复用同一个 `AgentState` 和同一个 `ToolApprovalGate`，否则无法证明没有创建时快照。

### 4.2 Memory 测试

调整 `MemorySystemPromptProviderTest` 和 `ManualAgentTest`：

1. `MemoryRuntime` 创建时读取 `AgentState.memoryEnabled()`。
2. 使用同一个 `MemoryRuntime`，关闭状态后 `loadIndex()`、`recall()`、`capture()` 和 `completeTurn()` 立即停止记忆流程。
3. 重新打开状态后，同一个对象恢复现有行为。
4. `ManualAgent.setMemoryEnabled(...)` 修改的就是共享 `AgentState`，并继续立即刷新 SESSION Prompt。
5. SubAgent 不新增 Memory Provider、recall 或 complete 调用。

只验证状态迁移，不改变原有 Memory 内容断言或网络测试协议。

## 5. 修改 `MemoryRuntime`

修改：

```text
src/main/java/dev/learn/agent/manual/memory/MemoryRuntime.java
```

删除：

```java
private boolean enabled;
```

新增唯一引用：

```java
private final AgentState agentState;
```

构造器从：

```java
MemoryRuntime(boolean enabled, AnthropicClient client, String model, WorkspacePathResolver paths)
```

改为：

```java
MemoryRuntime(AgentState agentState, AnthropicClient client, String model, WorkspacePathResolver paths)
```

所有判断点直接读取：

```java
agentState.memoryEnabled()
```

删除 `MemoryRuntime.enabled()` 和 `MemoryRuntime.setEnabled(...)`，不要保留委托方法。否则调用方仍可能把 `MemoryRuntime` 误认为开关状态的所有者。

MemoryRepository、MemoryRecallService、MemoryExtractor 和 MemoryConsolidator 仍由 `MemoryRuntime` 持有，它们属于执行资源，不进入 `AgentState`。

## 6. 修改 `ManualAgent`

`ManualAgent` 已因核心文档持有 `AgentState`。将：

```java
memoryEnabled()
setMemoryEnabled(boolean enabled)
```

改为直接读取和修改：

```text
agentState.memoryEnabled()
agentState.setMemoryEnabled(enabled)
```

`setMemoryEnabled(...)` 后继续执行原有 SESSION Prompt 刷新，顺序保持：

```text
先修改 AgentState
再 refreshFrom(SESSION, agentState)
```

不要把刷新逻辑放进 `AgentState.setMemoryEnabled()`；状态对象不应依赖 System Prompt 运行资源。

`ManualAgent.submit()` 的以下顺序保持不变：

```text
refresh SESSION
-> recall
-> 添加用户消息
-> capture
-> AgentLoop
-> completeTurn
```

## 7. 修改 `MemorySystemPromptProvider`

Provider 继续调用 `MemoryRuntime.loadIndex()`，不直接访问仓库。`MemoryRuntime.loadIndex()` 内部已经读取共享 `AgentState`，因此不需要给 Provider 同时注入两个对象。

不要缓存 `memoryEnabled`，也不要在 Provider 构造时决定是否注册。关闭记忆后 Provider 仍存在，只返回空内容；重新打开后同一个 Provider 才能恢复。

## 8. 修改 `ToolApprovalGate`

修改：

```text
src/main/java/dev/learn/agent/manual/tool/approval/ToolApprovalGate.java
```

删除：

```java
private final ToolApprovalMode mode;
```

新增：

```java
private final AgentState agentState;
```

构造器从固定 mode 改为共享状态：

```java
ToolApprovalGate(
        ToolApprovalPolicy policy,
        AgentState agentState,
        Scanner scanner
)
```

`approve()` 每次在 Policy 分类之后读取：

```java
agentState.approvalMode()
```

精确顺序保持：

```text
1. policy.requirementFor(effectiveToolCall)
2. NOT_REQUIRED -> true
3. 读取 agentState.approvalMode()
4. BYPASS -> true
5. ASK -> askUser(toolCall)
```

不能在构造器中把 mode 读到局部字段，也不能新增 `Supplier<ToolApprovalMode>`；共享状态本身就是所需依赖。

### 8.1 Scanner 约束

Interactive 必须继续注入 Scanner。Exec 的初始模式为 BYPASS，可以继续传 `null`。

如果 Gate 实际读取到 `ASK` 而 Scanner 为 `null`，直接抛出明确的 `IllegalStateException`，说明当前 Session 没有可用交互输入。不要把它静默降级为 BYPASS，也不要自动拒绝，因为这两种做法都会改变审批语义。

`askUser()` 继续保持 `synchronized`，动态状态迁移不改变并发终端读取约束。

## 9. 修改 Runtime 装配

在 `AgentRuntime.create(AgentState, Scanner)` 中：

```text
MemoryRuntime <- 同一个 AgentState
ToolApprovalGate <- 同一个 AgentState
ManualAgent <- 同一个 AgentState
parent AgentLoop <- 持有同一个 AgentState
subagent AgentLoop <- 持有同一个 AgentState
```

删除从 Runtime 参数或局部变量继续传递 `memoryEnabled`、`approvalMode` 的代码。

`ApplicationOptions.memoryEnabled()` 仍是启动输入，不是长期状态副本；它只在应用创建 `AgentState` 时读取一次，这不违反唯一状态规则。
