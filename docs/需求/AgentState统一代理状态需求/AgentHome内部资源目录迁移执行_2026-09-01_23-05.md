# AgentHome 内部资源目录迁移执行

## 1. 文档定位

本执行文档只迁移已经明确由 Agent 自身拥有的资源和运行记录，使其不再隐式依赖 `workspace`。

本轮迁移对象只有：

```text
skills/
.task_outputs/transcripts/
```

以下数据本来就属于当前 workspace，必须继续保存在 workspace，不属于 `agentHome` 迁移范围：

```text
.task_outputs/tool-results/
.transcripts/
.tasks/
.memory/
```

## 2. 已确认约束

### 2.1 `agentHome` 根目录来源

`agentHome` 来自固定的用户目录配置。当前由于启动目录就是代码所在目录，配置值与迁移前实际使用的目录相同。

实现不得新增 CLI 参数，也不得把配置值改成 `workspace/.manual-agent`、临时目录或其他未确认位置。应用层只负责把已配置路径写入 `AgentState.agentHome`；后续修改配置值时，Agent 自身资源即可切换到新的固定用户目录。

Interactive 和 Exec 使用同一配置值。

### 2.2 workspace 数据归属

以下归属已经确认，不再保留待定项：

- `workspace/.task_outputs/tool-results`：当前 workspace 中被截断的大工具结果。
- `workspace/.transcripts`：当前 workspace 的 Context 压缩前历史。
- `workspace/.tasks`：当前 workspace 的 Agent 任务系统状态。
- `workspace/.memory`：当前 workspace 的项目记忆。

这些路径继续从 `AgentState.workspace()` 派生。不得为了使用 `agentHome` 而改造 `TaskStore`、`ContextManager` 或 `MemoryRepository` 的存储根目录。

### 2.3 `allowedRoots` 不受本执行项影响

`allowedRoots` 初始值只包含 `workspace`。本执行项迁移的 `skills` 和终端 transcript 都不需要通过模型文件工具读取，因此不得把 `agentHome` 或其子目录自动加入 `allowedRoots`。

`allowedRoots` 未来可以包含更多目录，本执行项不得增加“只能包含 workspace”或“不能包含多个目录”等限制。

AgentState核心模型与Session装配执行_2026-09-01_23-05.md

## 4. 本轮明确不做

- 不迁移 `.task_outputs/tool-results`。
- 不迁移 `.transcripts`。
- 不迁移 `.tasks`。
- 不迁移 `.memory`。
- 不修改上述 workspace 数据的格式、读写协议或生命周期。
- 不设计旧目录自动搬迁或双读兼容。
- 不删除 workspace 中已有文件。
- 不新增配置文件、配置框架或通用存储抽象。
- 不把整个 `agentHome` 暴露给模型文件工具。
- 不改 Trace/OTel 输出；当前代码没有从 workspace 派生本地 Trace 目录的实现。

## 5. 目录映射

| 当前路径 | 执行后路径 | 处理方式 |
| --- | --- | --- |
| `workspace/skills` | `agentHome/skills` | 迁移路径来源 |
| `workspace/.task_outputs/transcripts` | `agentHome/.task_outputs/transcripts` | 迁移路径来源 |
| `workspace/.task_outputs/tool-results` | `workspace/.task_outputs/tool-results` | 保持 workspace |
| `workspace/.transcripts` | `workspace/.transcripts` | 保持 workspace |
| `workspace/.tasks` | `workspace/.tasks` | 保持 workspace |
| `workspace/.memory` | `workspace/.memory` | 保持 workspace |

本轮只替换前两项的根目录，不改变文件名、文件格式、UUID 生成、原子写入和清理行为。

## 7. 应用入口装配 `agentHome`

修改：

```text
src/main/java/dev/learn/agent/manual/ManualAgentApplication.java
```

应用入口读取已经确认的固定用户目录配置，并将其作为 `AgentState.agentHome`。如果当前配置值就是启动目录，测试和运行结果允许与迁移前落在同一实际位置，但代码中的路径语义必须来自 `agentHome`，不能继续从 `workspace` 偶然派生。

如果应用负责创建目录，顺序为：

```text
1. 取得配置的 agentHome 路径
2. Files.createDirectories(agentHome)
3. agentHome.toRealPath()
4. 用真实路径创建 AgentState
5. 再创建 transcript 和 AgentRuntime
```

创建失败直接抛出，不回退到 workspace，也不吞错。

Interactive transcript 把当前从启动目录派生的路径改为：

```java
agentState.agentHome().resolve(".task_outputs").resolve("transcripts")
```

Exec 当前不创建终端 transcript，本轮保持这一行为。

## 8. Runtime 路径装配

修改 `AgentRuntime` 中的 Skill 装配：

```java
new SkillRegistry(agentState.agentHome().resolve("skills"))
```

其他存储组件继续使用 workspace：

```text
TaskStore <- agentState.workspace()/.tasks
ContextManager tool results <- agentState.workspace()/.task_outputs/tool-results
ContextManager compressed history <- agentState.workspace()/.transcripts
MemoryRuntime/MemoryRepository <- agentState.workspace()/.memory
BashTool <- agentState.workspace()
GitMcpClient <- agentState.gitRoot()
```

不要修改 `TaskStore`、`ContextManager`、`MemoryRepository` 或 `SkillRegistry` 的文件格式和业务逻辑。`SkillRegistry` 已经接收目录，只需修改调用方传入的路径。

## 10. 旧数据处理

本轮不实现复制、移动、删除或双读。当前 `agentHome` 配置值与原启动目录相同，因此现有 skill 和终端 transcript 在本轮仍可按原实际路径访问。

未来只修改 `agentHome` 配置值时，是否搬迁旧的 Agent 自身数据必须另行确认，不得在本轮预埋迁移逻辑。

workspace 下的 `.task_outputs/tool-results`、`.transcripts`、`.tasks` 和 `.memory` 不是待迁移旧数据，后续仍由 workspace 使用。
