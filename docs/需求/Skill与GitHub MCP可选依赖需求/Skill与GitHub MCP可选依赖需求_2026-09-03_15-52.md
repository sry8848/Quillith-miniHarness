# Skill 与 GitHub MCP 可选依赖需求

## 需求描述

当前 `manual-agent` 在启动阶段强制初始化 Skill 和 GitHub MCP。Skill 根目录不存在时，`SkillRegistry` 无法完成构造；未配置 GitHub Token 或 GitHub MCP 初始化失败时，启动流程也会直接终止。

Skill 和 GitHub MCP 都属于增强能力，不是 Agent 完成基础对话、文件操作、任务管理以及其他已成功装配能力的必要条件。本需求将它们从启动必需依赖调整为可选依赖：某项能力不可用时只停用该项能力，不阻断 Agent 启动。

本需求的首要约束是控制实现复杂度。只修改 Skill 和 GitHub MCP 在现有启动装配流程中的必要判断与注册行为，不建设通用插件框架、可选依赖管理层或复杂的异常分类系统。

## 需求目标

完成改造后应满足：

- Skill 与 GitHub MCP 任意一项缺失时，Agent 可以正常启动。
- Skill 与 GitHub MCP 同时缺失时，Agent 仍可以正常启动。
- 不可用的能力不参与注册，其他不依赖它的能力继续按原流程工作。
- 能力存在且配置正确时，保持当前行为不变。
- Skill 路径存在但加载异常，或 GitHub MCP 缺失、不可用时，应使用 `WARN` 或 `ERROR` 日志记录原因，不能静默隐藏异常。
- Skill 或 GitHub MCP 的错误配置、加载失败和初始化失败都只停用对应能力，不阻塞 Agent 启动。
- 降级启动不能吞掉异常信息；日志应保留足以定位问题的原因。
- Skill 或 GitHub MCP 初始化边界内出现未预期异常时，也应兜住用户，记录包含异常堆栈的 `ERROR` 日志并继续启动。

## 概念边界

### 一、Skill 缺失

以下情况是合法、正常的零技能状态：

- 配置的 Skill 根目录不存在。
- Skill 根目录存在，但其中没有可注册的 Skill。

降级后：

- Agent 不提供可用 Skill 列表。
- Agent 不应向模型提供实际不可用的 Skill 能力。
- 基础工具和其他已成功初始化的能力不受影响。

以下情况属于 Skill 加载异常：

- Skill 根路径存在但不是目录。
- Skill 根目录存在但无法读取。
- 已存在的 Skill 定义格式错误、内容非法或名称冲突。

这些情况表明用户已经提供了 Skill 配置，但配置本身有问题。启动流程应记录 `ERROR` 日志并跳过整个 Skill 能力，Agent 继续启动。不能把此类错误只记录成普通的“没有安装 Skill”，也不能加载部分成功、部分失败的 Skill 集合。

Skill 根目录不存在或其中没有可注册的 Skill 时，不记录 `WARN` 或 `ERROR`，正常继续启动，并且不注册 Skill 工具或 Skill 提示。

### 二、GitHub MCP 缺失或不可用

以下情况视为 GitHub MCP 能力不可用，允许降级启动：

- 未配置 `GITHUB_PERSONAL_ACCESS_TOKEN`，或配置值为空白。
- GitHub MCP 服务无法连接。
- GitHub MCP 客户端或远程服务无法完成正常启动、初始化或工具发现。

降级后：

- 不向工具注册表注册 GitHub MCP 工具。
- 不影响本地 Git MCP、基础工具以及其他已成功初始化的能力。
- 后续流程不得对未创建或未成功初始化的 GitHub MCP 客户端执行关闭等生命周期操作。

未提供 Token 属于预期的能力缺失，记录 `WARN` 日志。已提供 Token 但认证失败，或者 GitHub MCP 在连接、初始化、工具发现过程中抛出异常时，记录 `ERROR` 日志并跳过 GitHub MCP，Agent 继续启动。

为了控制复杂度，本需求不要求新增一套通用异常分类机制。现有调用边界能够直接识别具体原因时，将原因写入日志；无法进一步分类时，保留原始异常信息并按 GitHub MCP 初始化失败处理。

### 三、未知异常处理

“兜住用户”与“吞掉异常”的边界如下：

- Skill 扫描、解析和注册期间的未知异常，由 Skill 初始化边界捕获。
- GitHub MCP 创建、连接、初始化、工具发现和注册期间的未知异常，由 GitHub MCP 初始化边界捕获。
- 捕获后记录 `ERROR` 日志，日志必须包含原始异常及堆栈，随后停用对应能力并继续启动。
- 不向用户抛出导致 Agent 整体退出的异常，但启动日志应明确说明哪项能力不可用。
- 只捕获这两项可选能力边界内的异常，不在整个 `AgentRuntime.create()` 或应用入口增加全局兜底。
- 工作目录、基础工具、模型客户端等必需能力的异常继续按原有方式失败，不属于本需求的降级范围。

这样既保证可选能力的未知故障不会中断用户使用，也保证内部保留完整诊断信息。

### 四、能力使用时的表现

可选能力缺失后，应通过“不注册对应能力”使模型和运行时自然无法调用它，而不是注册一个始终失败的占位工具，也不实现模拟或替代能力。

启动提示是能力缺失的主要反馈。若现有调用链仍可能触发对缺失能力的显式请求，则应返回明确的“能力不可用”错误，不应静默失败或吞掉调用。

## 场景与预期行为

| Skill 状态 | GitHub MCP 状态 | 预期启动结果 |
| --- | --- | --- |
| 可用 | 可用 | 正常启动并注册两项能力 |
| 缺失 | 可用 | 按正常零技能状态启动，只注册 GitHub MCP，不记录 Skill 日志 |
| 可用 | 缺失或不可用 | 正常启动，只注册 Skill |
| 缺失 | 缺失或不可用 | 按正常零技能状态启动，不注册两项能力 |
| 空目录 | 任意状态 | 按正常零技能状态启动，不记录异常日志 |
| 配置存在但加载失败 | 任意状态 | 记录 `ERROR`，跳过 Skill 并继续启动 |
| 任意状态 | 配置存在但认证或初始化失败 | 记录 `ERROR`，跳过 GitHub MCP 并继续启动 |

## 复杂度约束

本次实现必须遵守以下约束：

- 优先在 `AgentRuntime` 现有初始化和工具注册位置进行局部修改。
- 不新增通用的可选能力接口、插件生命周期框架或依赖注入层。
- 不为 Skill 和 GitHub MCP 建立统一状态机。
- 不增加可配置的重试、熔断、自动恢复或后台重连机制。
- 不增加覆盖整个应用启动流程的全局 `catch`；异常捕获范围只覆盖 Skill 和 GitHub MCP 各自的初始化边界。
- 不为了消除少量条件判断而创建只使用一次的包装类或辅助抽象。
- 不修改与本需求无关的本地 Git MCP、基础工具、AgentLoop 或任务系统。
- 不借本次修改重构附近代码或统一所有 MCP 的异常处理方式。
- 只保留完成当前需求所需的提示、条件判断、资源清理和测试。

## 不在本次范围内

- 不移除 Skill 或 GitHub MCP 功能。
- 不支持运行期间动态安装、卸载或重新加载 Skill。
- 不支持运行期间动态启用、重连或重新注册 GitHub MCP。
- 不提供 GitHub MCP 的替代实现或离线实现。
- 不改变本地 Git MCP 的可选注册行为。
- 不改变现有配置来源和 Token 获取方式。
- 不设计适用于所有未来工具和 MCP 的通用降级方案。

## 调研与决策记录

### 当前状态

- `AgentRuntime.create()` 会直接读取 `GITHUB_PERSONAL_ACCESS_TOKEN`，缺失或空白时立即抛出异常。
- `AgentRuntime.create()` 会无条件创建 `SkillRegistry`，而 `SkillRegistry` 构造时要求 Skill 根路径能够解析为真实目录。
- `AgentRuntime.create()` 会无条件创建并注册 `GitHubMcpClient`。
- 当前本地 Git MCP 已采用条件创建方式，本需求不重复调整该能力。

### 已确认决策

1. Skill 和 GitHub MCP 调整为彼此独立的可选能力。
2. 未配置、未安装或外部服务暂时不可用时，记录 `WARN` 或 `ERROR`，跳过对应能力并继续启动。
3. 已存在但错误的配置也不阻塞启动；通过 `ERROR` 日志保留真正需要修复的问题。
4. 通过现有装配点的最小修改实现，不抽象成通用机制。
5. 能力缺失时不增加功能兜底，只明确提示并停止注册该能力。
6. 可选能力初始化边界内的未知异常必须记录完整异常堆栈，然后降级启动；这不等于静默吞掉异常。

## 验收条件

- 删除或不提供 Skill 根目录时，Agent 按正常零技能状态启动，不记录 `WARN` 或 `ERROR`，且不注册 Skill 能力。
- Skill 根目录为空时，Agent 按正常零技能状态启动，不记录 `WARN` 或 `ERROR`，且不出现虚假的可用 Skill。
- 不提供 `GITHUB_PERSONAL_ACCESS_TOKEN` 时，Agent 能正常启动，并明确提示 GitHub MCP 未启用。
- GitHub MCP 因连接、启动、初始化或工具发现失败而不可用时，Agent 能继续启动，且不注册部分初始化的 GitHub 工具。
- Skill 与 GitHub MCP 同时不可用时，Agent 仍能使用基础能力。
- Skill 或 GitHub MCP 存在且有效时，其行为与改造前一致。
- Skill 配置内容错误或加载失败时，记录包含原因的 `ERROR` 日志，跳过全部 Skill 并继续启动。
- GitHub 配置错误、认证失败或初始化失败时，记录包含原因的 `ERROR` 日志，跳过 GitHub MCP 并继续启动。
- GitHub Token 未配置时，记录 `WARN` 日志并继续启动。
- Skill 或 GitHub MCP 初始化期间发生未知异常时，`ERROR` 日志中保留原始异常堆栈，Agent 不因此退出。
- 两项可选能力之外的启动异常不会被该降级逻辑捕获。
- 启动失败或正常退出时，只关闭实际创建成功的资源，不因可选客户端不存在产生新的异常。
- 实现没有引入通用框架、重试机制或与需求无关的重构。

## 最小测试范围

只覆盖本需求的关键分支：

1. Skill 与 GitHub MCP 均可用。
2. 仅 Skill 缺失。
3. 仅 GitHub MCP 缺失。
4. Skill 与 GitHub MCP 同时缺失。
5. Skill 配置明确错误。
6. GitHub MCP 配置明确错误。

不为无法稳定构造的外部网络故障建立复杂集成测试；GitHub MCP 初始化失败分支可以在现有测试结构允许的范围内使用最直接的替身或边界测试验证。
